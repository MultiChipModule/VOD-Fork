# Playback reporting and lower original variants

## What changed

Jellyfin Web's quality menu sends a new maximum bitrate while keeping the current media source ID. Jellyfin filters to that source before it applies the device profile. If the source is over budget, this can cause video encoding even when YouTube has an original lower rung. VOD now publishes bounded AVC rungs at or below 720p, 480p and 360p when available. For an over-budget pinned source it can select a lower, probed original with compatible video and matching requested audio and subtitle tracks before the normal PlaybackInfo action. Jellyfin still owns the final codec decision, bandwidth policy, remux, session ID and resume time. Different codecs, mismatched track indices and unknown bitrates retain native fallback behavior.

Jellystat polls Jellyfin's native Sessions response. It uses the now-playing item and its series metadata for activity. A hidden alternate reported as ItemId is an identity mismatch for catalog consumers. VOD now normalizes such native YouTube start, progress and stop reports to the visible primary item with the actual played version as MediaSourceId. It does this only when Jellyfin confirms both items and the played version are visible to the authenticated user and belong to the same VOD group. Native playback endpoints still handle all events, preserving the playback session, seek position and per-version progress. Existing reports with the correct primary item are unchanged. This fixes the identifiable alternate-report case. The cause of the missing production Jellystat entries remains unconfirmed without a comparison of Jellyfin Sessions and Jellystat activity.

## Update and verify

Back up the installed plugin directory, install the patch from the existing catalog and restart Jellyfin. Let VOD's normal publication reconcile the available lower rungs. No setting change is needed. The first request can probe an unprobed variant. Try a reduced bitrate with a known compatible original and check the Jellyfin FFmpeg log for video and audio copy. Verify the selected track and resume position. The new FFmpeg fixture lowers the bitrate, remuxes from one second in and checks the decoded video plus AAC audio. It does not exercise the TrueNAS server or Apple TV.

Enable **Log YouTube playback negotiation (for troubleshooting)** for the following checks:

- **Jellystat.** Play one VOD item long enough to cover Jellystat's polling interval. Check whether native Jellyfin shows the canonical item as now playing while its play state has the actual source ID. Compare the matching **VOD native playback report** entries and native HTTP status with a working title. If the canonical item appears in Jellyfin's Sessions response but not Jellystat, collect the Jellystat activity interval and catalog sync status for that item. No session simulation or synthetic reports were added.
- **Swiftfin on Apple TV.** Swiftfin uses Jellyfin's negotiated subtitle delivery. Both VOD English tracks already have the same external WebVTT registration and authorization. Switch to each track on the same video and collect the **VOD PlaybackInfo**, **VOD external subtitle request**, HTTP status, and whether you were using the native or alternate player. A missing request points to selection or negotiation. A successful response with no on-screen text calls for comparing cue timing and payload format. Neither actual payload nor a device trace was available, so this release does not change working subtitle formatting.
- **Infuse.** The unresolved distinction is whether Infuse requests native dynamic HLS or requests a static, range-addressed media resource. Capture one failed attempt with the existing **VOD PlaybackInfo** and **VOD media request** diagnostics. Record the action, method, status, content type and whether there was a Range header. Remove tokens, signed URLs and private hostnames. No new endpoint or unverified client-specific playback path was added.

For rollback, stop Jellyfin and restore the backed-up plugin directory and metadata, or select the confirmed working **5.1.2.0** release from the catalog. Keep the playback libraries and the existing VOD database.
